# Production local first increment

Production now contains Items, Jobs & task board, Job workers, Item parts, Item sizes, Designs, Stages, Stage types, Part names, Sizes, Product types, Job statuses and the existing Brands page. The supporting pages reuse the same master form, confirmation, Overview, protected Sheet, formatting/export/print. The jobs Overview is a stage board with sent versus final completed/received totals. It includes empty configured stage lanes. Main search accepts item style codes from keyboard-wedge QR scanners or manual entry; no camera scanner is claimed.

The read-only schema inspection confirmed item → item_part → job → design_per_job → stage_pieces. Sizes are item_size_list records referencing size_list, and stage_pieces is unique per design_per_job + item_size_list. Job codes and relevant FK names retain the live schema shape. Job workers refer to shared contacts/contact categories. Brand records remain shared with Colours; the existing simplified Brands editor has not been expanded to its full contact relationships in this increment.

The explicit job editor shows item style, item part, stage, worker, status, dates, verifier, design and per-size final counts. Every entered count must be a non-negative integer. Resaving a count updates the same row rather than incrementing or duplicating it. Existing linked designs stay fixed; new designs can be added. Blank counts stay unchanged; zero records zero. Review shows all job header values and size counts before confirmation. Stages without track_pieces do not display piece-entry fields. Prior-stage quantities are shown for the same item part, matching design and size, using the nearest earlier stage order; they are a reference, not a fabricated receipt or automatic job dependency.

The local sample is SC-101 with Body/Sleeve parts and S/M/L sizes, completed Cutting counts and a Printing job awaiting output. Existing Fabric/Inventory/Miscellaneous data is preserved; older empty production collections receive the sample without overwriting existing items or IDs. Inventory item-part pickers now see these shared records. Parent/child/link validation rejects missing refs, duplicate item/part and item/size assignments, duplicate design/size final counts, mismatched sizes and invalid date order. Older colour migration permits a missing obsolete brand link to become null, rather than creating a dangling item FK.

## Explicitly still pending

This is a coherent first increment, not the full production rollout. Challan creation/printing is next; existing challan tables are read only for outbound totals. Camera scanning, printed QR job sheets, live employee validation and a shareable floor-link entry are not implemented. The eventual floor and authenticated routes must reuse this same final-count flow, with employee validation enforced by the real backend. TNA, parallel part/job dependencies, schema changes, live writes, shared business persistence and automatic production numbering remain separate work.

All records are local sample data. No production DB tables, data, Auth settings or grants were changed. New page permissions are generated from the page catalogue; existing custom roles receive no automatic grants. Administrator sees the pages; real account integration still requires the parent user-management work.

## Combined item editor

Item creation/editing now includes size selections with whole non-negative cutting pieces, horizontally arranged variant-name cards and part/colour selectors. Database inspection confirmed item_cut_ratio(item_size_list_id,pieces) and variant(item_part_id,design_id,color_map_id); user-facing terminology is Variant while existing database design IDs/names remain unchanged. Item parts reuse the item + part_list mapping across variants. Colour is optional as in the schema. The review connects the item/size quantities to variant cards and their parts/colours before confirmation. This remains local sample persistence, with no live writes or schema changes. Child removal is intentionally not exposed yet; existing mappings and downstream jobs are preserved.
