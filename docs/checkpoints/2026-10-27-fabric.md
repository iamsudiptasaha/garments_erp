# Fabric checkpoint — 27 October 2026

## Review entry points

From `fabric-poc/`, run `npm ci` and `npm run dev`, then open `/fabric.html` (or `/`). `/fortune.html` retains the standalone protected-sheet trial. Other library comparisons are retained at `/univer.html` and `/tabulator.html`.

## Agreed and implemented

- Fabric has Overview and protected Sheet views, with expandable navigation for later modules.
- Colours is a separate top-level section with Colour library and Colour mappings.
- Bill forms keep one parent header and many child lines, with review/confirmation and atomic local validation.
- Yarn orders/receipts, knitting, colour-grouped dyeing programs, dyed receipts, balances and batch traceability share linked records.
- Colour mapping is required on dyeing program lines. Batch is optional, follows the existing nullable FK and is selectable only from that exact mapping's associated receipt batches. Changing the mapping clears the batch selection.
- Mapping labels display colour / brand. Attached-swatch status comes from the colour master and appears in mapping data.
- Sheet values cannot be changed directly. Add/Edit forms change business data. Native formatting remains available; sorting moves complete records and shows its direction in the active heading.
- Browser-local persistence, CSV and formatted flat print preview are implemented. Final printer/PDF output still needs target-browser verification.
- Local and GitHub CI quality gates cover lint, unused code/dependencies, duplicate blocks, tests, build and dependency advisories.
